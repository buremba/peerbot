## The no-change-week verification — this found a real bug

Checking the property you asked me to verify is what exposed it. `generatedAt` was stamped with today's date on **every** run, so an unchanged upstream still rewrote that line:

```
-  "generatedAt": "2026-07-27",
+  "generatedAt": "2026-08-03",
```

That's an empty churn PR every Monday — which trains reviewers to rubber-stamp exactly the diffs that need reading, defeating the point of using a PR. I fixed it at the root (the generator now preserves the previous stamp when nothing but the date would change) rather than working around it in the workflow with a fragile one-line `git checkout` dance.
