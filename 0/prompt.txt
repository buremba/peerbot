## The truth I found

The audit was right that `asOf` was declared-and-throwing, but the shape of the gap is different from "the compiler needs a point-in-time engine":

- `MetricReadMode = 'current' | 'raw' | { asOf: string }` lives in `packages/connector-sdk/src/metrics.ts:27`, is re-exported by the CLI config (`packages/cli/src/config/define.ts:71`), and its doc comment **already settles the semantics**: `asOf` compares against `occurred_at` — *event time, NOT system time*.
- `packages/server/src/metrics/compiler.ts` threw `MetricNotImplementedError` for anything but `"current"`.
- So the whole feature is one predicate on a relation the compiler already builds. It is genuinely mechanical — the hard part is only choosing the right temporal semantics and not silently getting the boundary day wrong.

## What I built

`packages/server/src/metrics/read-mode.ts` (new) lowers `reads` into a predicate ANDed into the existing inner events filter, **before** dedupe/segment/aggregate:

- date-only `2026-03-31` → `occurred_at &lt; '2026-04-01T00:00:00.000Z'::timestamptz` — read as the *end* of that UTC day, which is what "the balance on 31 March" means. Taking it literally as `&lt;= 2026-03-31T00:00:00Z` would silently drop the whole day; that off-by-one is the main trap and it has a dedicated test.
- explicit instant → `occurred_at &lt;= '…'::timestamptz`, inclusive.
- offset-less timestamp (`2026-03-31T12:00:00`) is **rejected**: Postgres resolves it in the session timezone, so the same config would answer differently on two replicas.
- `'raw'` stays NotImplemented, deliberately — `validateAndScopeQuery` rewrites `events` → `current_event_records` unconditionally, so the compiler cannot express "include superseded rows" as a predicate.
- Malformed `asOf` now fails at **apply** (`manage_entity_schema.assertValidMetricsConfig`), not at first query.

I deliberately did **not** touch `@lobu/connector-sdk` or any MCP tool schema, so no API/SDK surface changed (see proposals below).

One non-obvious bug the tests caught that a typecheck never would: I first emitted `TIMESTAMPTZ '…'`, which is valid Postgres but **`@polyglot-sql/sdk` fails to parse it**, so `validateAndScopeQuery` threw `Could not parse SQL query for table extraction` on every asOf query. The `'…'::timestamptz` cast form is required, and there's now a comment saying why.

## The invariant — my explicit position

**`asOf` does not introduce an aggregation-over-history read path; it strictly narrows one that already shipped.** The compiler's `GROUP BY` over `events` is pre-existing, in the `current` read, and `asOf` adds one range predicate and nothing else — no join, no `DISTINCT ON`, no per-row `regexp_*`, no leading-wildcard `LIKE`. If that `GROUP BY` violates the invariant, it violates it today for `current`, and fixing it means materializing the *whole metric layer*, not gating this feature.

I measured rather than assumed. 1,000,001 events, single entity, embedded Postgres, `EXPLAIN (ANALYZE, BUFFERS)` on the real scoped SQL, 5 runs each:

| measure | median e2e | EXPLAIN exec | rows scanned |
|---|---|---|---|
| `balance` (current, already shipped) | 379.3 ms | 398.5 ms | 1,000,000 seq scan |
| `balance_asof` (new) | 313.7 ms | 334.1 ms | 812,584 seq scan (187,417 removed by the asOf filter) |

So `asOf` is ~17% **cheaper** than the current read it derives from, exactly proportional to the rows it excludes, on an identical plan shape. This matches the benchmark you cited (sub-200ms-class single-customer balance reads at 1M rows) — no write-time materialization machinery is needed here, and I'd have been wrong to build it.

The honest caveat: both plans are **sequential scans**, so this path is O(org history) already. `asOf` inherits that; it does not create it. The scan is bounded by org history in prod (org-scoping uses `idx_events_organization_id`; my single-org benchmark is the worst case).

Where the invariant *would* genuinely bite is **system-time** `asOf` ("what did we believe on 31 March"), which needs a per-row supersede-chain walk (`superseded_by` + the superseder's `created_at`). That is the shape that must be materialized at write time. `read-mode.ts` refuses it rather than compiling it, and both it and the compiler header document why.
