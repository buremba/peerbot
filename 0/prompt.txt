## 2. Key Technical Concepts

- **Two cursors on a Behavior**: schedule cursor (`watchers.next_run_at`, now-based, never replays) vs window cursor (`max(canvas_windows.window_start)`, +1 period per *completed* window, capped at current period but never jumping to it). Wall-clock advances one period per period → lag freezes rather than closing.
- **`complete_window` takes no period** — it derives the window entirely from `window_token`, which is minted from agent-supplied `since`/`until` in `read_knowledge`. Nothing validates it against the dispatched window. Therefore an agent can already choose its own window and unstick the cursor.
- **Two response surfaces**: MCP `tools/call` → `markdown-formatter.ts` (prose); **Behavior runs** → `run_sdk` → `client.knowledge.read()` → **raw JSON, no formatter**. This distinction is the crux of the session.
- **Agent-native design** (user's principle): surface state + affordance, don't encode policy in the server, because agent capability rises over time.
- TypeBox contracts, `@hey-api/openapi-ts` client generation, `client-regen` CI gate.
- `alignToBehaviorWindowStart` / `addBehaviorPeriod` from `@lobu/connector-sdk` — all `setUTC*`.
- `parseDateAlias` normalizes to **local** midnight — conflicts with UTC window boundaries in both directions.
- Mutation testing discipline; `make pre-pr` (6 gates), `make review-fix`, `make review`.
- Prod: CNPG `lobu-ai-prod-db`, DB `owletto`, ns `summaries-prod`.

```ts
export function parseBehaviorWindowDate(value: string): Date {
  const trimmed = value.trim();
  if (/^\d{4}-\d{2}-\d{2}$/.test(trimmed)) {
    return new Date(`${trimmed}T00:00:00.000Z`);
  }
  const local = parseDateAlias(trimmed).date;
  return new Date(Date.UTC(local.getFullYear(), local.getMonth(), local.getDate()));
}

export function alignRequestedWindow(since, until, granularity): { windowStart: Date; windowEnd: Date } {
  const windowStart = alignToBehaviorWindowStart(since, granularity);
  const alignedUntil = alignToBehaviorWindowStart(until, granularity);
  const windowEnd = addBehaviorPeriod(alignedUntil < windowStart ? windowStart : alignedUntil, granularity);
  return { windowStart, windowEnd };
}

export function computeWindowLag(cursor, now, granularity): { currentPeriodStart: Date; periodsBehind: number } {
  const currentPeriodStart = alignToBehaviorWindowStart(now, granularity);
  if (!cursor) return { currentPeriodStart, periodsBehind: 0 };
  const alignedCursor = alignToBehaviorWindowStart(cursor, granularity);
  const periodsBehind = wholePeriodsBetween(alignedCursor, currentPeriodStart, granularity);
  return { currentPeriodStart, periodsBehind: Math.max(0, periodsBehind) };
}

export function describeWindowLag(lag: {
  lastWindowStart: Date | null; currentPeriodStart: Date;
  periodsBehind: number; granularity: BehaviorTimeGranularity;
}): string | null {
  if (lag.periodsBehind < 2 || !lag.lastWindowStart) return null;
  return (
    `This Behavior is ${lag.periodsBehind} ${lag.granularity} period(s) behind. Its last ` +
    `completed window starts ${lag.lastWindowStart.toISOString()}, but the current period ` +
    `starts ${lag.currentPeriodStart.toISOString()}. The cursor advances only ONE period per ` +
    'completed window, so it will not catch up on its own. The window you complete is whatever ' +
    'span you read: call read_knowledge again with `since`/`until` and complete the token it ' +
    'returns. Completing a recent period moves the cursor forward to it; completing an older ' +
    'one never moves it back. Decide from this Behavior\'s purpose whether the skipped periods ' +
    'are worth analysing or whether only the current period matters.'
  );
}
```
Plus private `wholePeriodsBetween` (O(1) arithmetic per granularity) and `monthsBetween`.
