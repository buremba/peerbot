## 2. Member resolution across platforms

**Storage model:** all identities are rows in **`entity_identities`** `(organization_id, namespace, identifier) → entity_id`, live-unique per org (partial unique index WHERE deleted_at IS NULL). There is no separate platform-identity table; the "platform-identity→user consolidation" landed as everything pointing into this one table at a `$member` entity.

- **Web login:** on sign-in/org provisioning, `provisionMemberAndCoreIdentities` creates the `$member` and writes an `auth_user_id` claim with `source_connector='auth:signup'` — `/Users/burakemre/Code/lobu/packages/server/src/auth/personal-org-provisioning.ts:191-203` and `/Users/burakemre/Code/lobu/packages/server/src/utils/member-entity.ts:134-144`. The member entity itself is found-or-created **by email** in `metadata` (member-entity.ts:84-124), with a guard refusing to provision when the user doesn't own the email (:72-82). The `auth:signup` source is the anti-hijack fence: authz resolution only trusts claims with that source (see below).
- **Generic namespaces:** `email`, `email_domain`, `phone`, `auth_user_id` registered in `/Users/burakemre/Code/lobu/packages/connector-sdk/src/identity-namespaces.ts:38-43`; connector-specific ones (slack_user_id, github_login, x_user_id…) are owned by each connector package (identity-namespaces.ts:1-12).
- **Slack:** namespace `slack_user_id`, always **team-scoped `T…:U…`** because "Slack user IDs aren't globally unique" — `/Users/burakemre/Code/lobu/packages/connectors/src/slack-identity.ts:19-45` (`normalizeSlackUserId`).
- **Slack message author attribution:** the transcript path maps a raw inbound author through `/Users/burakemre/Code/lobu/packages/server/src/gateway/connections/sender-identity.ts:36-60` (`buildSenderIdentity`: bot → null; slack → `{namespace: slack_user_id, identifier: T:U, mintEntityType: 'person'}`), then the connector-agnostic resolver in entity-link-upsert looks it up / mints a `person`; the message row stores `author_entity_id` (migration `20260630130000_channel_messages_attribution.sql:4` "map a captured message to the person/$member entity that wrote it").
- **Two platforms, one human — three convergence mechanisms:**
  1. *Identity-first, type-agnostic collapse:* the ACL graph builder resolves each member onto "any existing entity (`$member`, `person`, …) carrying ANY of their identities; only genuinely-new members get a freshly-created `person`" — `/Users/burakemre/Code/lobu/packages/server/src/authz/access-graph.ts:128-140` (and header :18-22).
