2. **Key Technical Concepts:**
   - **Two-tier credential design → collapsed to one tier**: "lease" (short-lived provider-derived token, GitHub App installation tokens ~1h, injected as a real env var) is now the ONLY tier. The "placeholder" tier was removed because the worker egress proxy raw-tunnels HTTPS CONNECT and cannot swap a placeholder inside TLS.
   - **`agentTooling` declaration** on `ConnectorDefinition`: `{nix?: {packages}, env?: [{name, credential: 'lease'}], domains?: string[]}`, persisted to `connector_definitions.agent_tooling` jsonb.
   - **Signed-token-vs-request-body boundary**: egress allowlist (and, in the new work, the package list) must ride the signed worker token claim, never the request body — the worker is the sandbox-ee.
   - **Resolution ordering invariant**: tooling resolves BEFORE `buildDeploymentWorkerToken` (so domains land in the signed claim that remote runtimes trust) and BEFORE `syncNetworkConfigGrants` (whose PG reconcile would otherwise revoke them).
   - **Reserved env names**: the contribution merges OVER an already-built base env, so WORKER_TOKEN/PATH/proxy vars must be rejected.
   - **Vercel persistent sandboxes**: `Sandbox.getOrCreate({persistent: true, name})` with a deterministic name per (org, agent, conversation); the filesystem is the persistent source of truth. `LOBU_VERCEL_SANDBOX_SNAPSHOT_*` are passthroughs to Vercel's own retention GC, NOT a package-set image cache.
   - **Repo gates**: `make test-unit`, `make pre-pr`, `make review-fix` (edits working tree; rewrites product copy — must verify), explicit-path staging, `make review` once on settled HEAD, `gh pr merge --squash --admin`.
   - **Known traps hit**: stale core dist requires `make build-packages`; deployments are in-memory in local dev so a restart is needed to clear the per-pod mint cache.
