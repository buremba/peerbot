2. **Key Technical Concepts:**
   - **Drift gate for `lobu apply`**: fail closed on un-declared remote state rather than overwriting or auto-deleting under `prune`.
   - **Three-way attribution**: `desired` (config) / `remote` (cloud) / `attribution` (effective remote after last succeeded apply). Converge when `remote == attribution`; block when `remote ≠ attribution AND desired ≠ remote`.
   - **`owned` set**: kind-qualified incarnation identities (`entity-type:12`, `watcher:b-1`, `connector-definition:5`) gating delete eligibility.
   - **`recorded` flag (new this session)**: distinguishes "no baseline was ever recorded" from "a recorded baseline that happens to be empty."
   - **Baseline storage**: `{attribution, owned}` inside the deployment event's `payload_data.manifest`, read via `GET /api/<org>/deployments/latest`.
   - **Partial index** `events_succeeded_deployments_idx` on `(organization_id, id DESC) WHERE semantic_type='change' AND metadata->>'category'='deployment' AND metadata->>'status'='succeeded'`.
   - **`pi-review` thresholds** (`docs/REVIEW_SCHEMA.md`): passes only when `bug_free>=80`, `slop<=15`, `simplicity>=70`, `bugs==0`, `blockers==[]`, `tests_adequate==true`. Per-run override `PI_REVIEW_MIN_SIMPLICITY=<n>`.
   - **`make pre-pr-remote`**: full Linux CI on Depot against the *staged* tree; records a tree-hash attestation `make review` requires.
   - **Tier analysis of the feature**: tier 1 = omitted⇒unmanaged (~30 lines); tier 2 = `owned` set (~80 lines); tier 3 = attribution baseline (~1400 lines + server route + migration).
