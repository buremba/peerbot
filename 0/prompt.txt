## 2. Key Technical Concepts

- **Behavior-as-writer vs Behavior-as-reaction** — the central architectural distinction. A Behavior that *performs* a write can enforce (atomic, in-transaction). A *reaction* cannot (post-commit, read-only sandbox).
- **`runMutationGate` runs inside `sql.begin`** with `sql: tx`, holding the row's `FOR UPDATE` lock (`entity-management.ts:696`). This is a true chokepoint.
- **Reactions are post-commit** — `manage_entity.ts` comment at the `queue()` call: *"Post-commit: ... queue() runs AFTER the entity tx + change event so the approval (run + event + notification) is never rolled back with the edit."*
- **Sandbox forces `SET TRANSACTION READ ONLY`** at `sandbox/client-sdk.ts:263`.
- **Declared outputs are atomic** — `promoteBehaviorEntityOutput` takes a `tx`; *"Duplicate exact keys and unexpected persistence errors fail the completion transaction: declared outputs are an atomic contract, not a best-effort side channel that may silently lose rows"* (`promote-keyed-entities.ts:438`); on error *"rolling back window completion"* (`:667`); savepoints at `:214`. `outputs?: Record<string, BehaviorOutput>` — plural named arrays.
- **`entity-hooks.ts` has only `beforeCreate` / `afterCreate` / `beforeDelete`** — **no update hook**, and `EntityHookContext` carries only `organizationId`, `userId`, `env` — no tx.
- **Three write-path gaps proven in prod:** (a) a declared `default` does NOT satisfy a `required` field on create; (b) `entities.update` validates the PATCH not the merged result; (c) a soft-deleted entity still holds its name.
- **`lobu link`** binds a directory to (context, org) in `.lobu/project.json` and **arms `apply`'s project-link guard** (`--force` = "Bypass the project-link guard if context/org don't match").
- **`lobu memory exec` takes inline source, not a file path.**
- **`entity_types` is NOT in the SDK sandbox queryable allowlist** (allowed: behavior_versions, behaviors, canvas_windows, channel_messages, connections, connector_definitions, entities, entity_relationship_types, entity_relationships, event_classifications, events, feeds, oauth_clients, oauth_tokens, user).
- **`consecutive_failures` is on `feeds`**, not `connections`.
- **Prod DB pod renamed** to `lobu-db-prod-1`; namespace `summaries-prod`; DB name `owletto`; `organization` uses camelCase `createdAt`.
- **ERP category invariant:** every serious ERP has a non-bypassable transaction-bound write chokepoint plus an in-transaction hook — Odoo ORM `write()` + `@api.constrains`; NetSuite record submit + `beforeSubmit`; Salesforce DML + `before update` trigger.
