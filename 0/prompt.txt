## 5. Problem Solving

**Core diagnosis:** the connector pages are a 1:1 projection of the schema — six tables became six tabs, and for a chat connector four of eight cells render empty states. Every prior round of feedback moved margins around that structure without touching it.

**Design rule established:** *"A screen per user decision, not a tab per table."* Four decisions (connect, choose scope, fix, disconnect) and two things read (is it healthy, what does it give my agents).

**Tabs verdict:** no detail tabs — tabs require that every tab has content for every instance, the set is stable, and panels are peer alternatives. None hold. Tabs survive only at the top-level resource split, and there as chips.

**Chips resolution:** chips as *filters* over one overlapping list = wrong; chips as *navigation* between disjoint resources = right, and it retires the awkward "Already set up for you" heading.

**Scale answer (most recent work):** connector grouping returns as an **overflow behaviour** using `useConnectionConnectorGroups` (already fetched) — one connection stays one row, 2+ collapse into a group; broken items pin above grouping; `CONN_CAP=20`, `FEED_CAP=8`, search above 12; unbound/failing feeds sort to the top. Demonstrated live via a "Busy workspace" toggle.
