2. **Key Technical Concepts:**
   - **Slack ACL gate:** `authz_source_acl_state` per (org, connection); enforcement requires `acl_support='full'` AND `freshness_state='fresh'` AND synced within `ACL_STALE_AFTER_MINUTES = 60`. Three states: `enforced`, `stale` (row exists but not enforcing → **fails closed**), `not-graphed` (no row → legacy per-agent fence). `acl_support` CHECK allows `('none','partial','full')`, defaults `'none'`.
   - **`acl_support='full'` is only ever set by `markAclEnforced`**, which runs only after a successful graph build — so a `full|failed` row proves the connection worked at some point.
   - **`max(last_synced_at)` is a group aggregate and ignores NULLs** — reading it as a per-row fact produces false "regressed on date X" conclusions.
   - **Webhook verification order:** `routes/public/app-webhooks.ts:1066` runs `provider.verify(...)` → 401 BEFORE the Slack takeover (comment at 1073: "Providers that own their own routing (Slack) take over here, after the edge signing check"). The adapter's own `verifySignature` is a *second*, later check inside `forwardWebhook`.
   - **`current_timestamp` = transaction start; `clock_timestamp()` = statement time.** Mixing them across a fence and its writer creates a race.
   - **AJV singleton runs with `coerceTypes`** — `null` becomes `""`/`0`; it mutates its input in place, so validating a filtered copy requires copying coercions back.
   - **`sql.begin(async (tx) => ...)`** is the repo transaction idiom; advisory-lock keys are int constants (e.g. `REAPER_ADVISORY_LOCK_KEY = 0x726e7372`).
   - **Prod deploy:** manifests live in the **owletto** repo (`gitrepository/flux-system → github.com/lobu-ai/owletto.git`, `kustomization apps .spec.path = ./deploy/k8s/apps/lobu/overlays/lobu-prod`).
