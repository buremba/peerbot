### The two corrections

1. **"A private MCP connection that only exists for the identity that created it"** — true of the *connection/credentials*, not the *server registration*. The connector definition (and its discovered tool catalog) is org-level and visible to the whole org; what's private is your connection and its credential. There is no per-user server registration.
2. **"Each user attaches their own Google credentials"** — the plumbing exists (per-connection oauth_account profiles, trigger-forced private), but a connector installed from a bare `mcp_url` gets `authSchema: null` (connector-definitions.ts:254), so it's unauthenticated out of the box; per-user OAuth attachment requires the connector definition to declare an auth schema (e.g. a source-installed connector carrying both `mcpConfig` and `authSchema`). I found no automatic upstream-MCP OAuth discovery (RFC 9728 / WWW-Authenticate) on the proxy path — the `www-authenticate` code in the repo is Lobu acting as its own OAuth/MCP *server*. Minor nuance: tool *discovery* (`discoverTools`, client.ts:176-200) uses the org's most-recently-updated credentialed connection without a visibility filter, but that only builds the tool catalog; actual calls are per-connectionId and visibility-gated.

### Corrected public-safe phrasing

&gt; Remote MCP servers are installed as connectors at the org level — you point Lobu at an MCP URL (or ship a connector that declares an upstream MCP) and its tools become org-visible operations. Credentials live one level down, on connections: each user can create their own connection to the same MCP connector, and personal OAuth credentials are forced to private visibility (a DB trigger rejects org-visible personal creds outright), so agents acting for other users can't route through your token. Tool calls always execute against a specific connection, so two users hit the same MCP server with two different credential sets. The one nuance: the server registration itself (and its tool list) is org-visible — what's private is your connection and credential, not the server's existence — and per-user OAuth against an upstream MCP needs the connector to declare an auth schema; a bare URL install is unauthenticated by default.
