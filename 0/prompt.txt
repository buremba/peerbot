5. **Problem Solving:**

   **Round 2 — seven gaps reduced to one.** Verified against code: history mechanism capable but (I thought) unused; freeze hook EXISTS and is designed for extension; state machine merges into the same interceptor (JSON Schema cannot express old→new transitions in any draft, so no library solves it); row-level authz via relationships is exactly what `access-graph.ts` already does, just aimed at `events`; Lobu is NOT event-sourced for entities so event-sourcing patterns don't apply; concurrency half-solved by `FOR UPDATE` + `field_controls`; **aggregates were the one surviving architectural gap.**

   **Round 3 — the extensibility asymmetry.** Every declarative layer (schema, event_kinds, metrics_config, backing_sql, view templates) is agent-authorable at runtime through `manage_entity_schema` with no deploy. **The write gate is the only layer that isn't** — `registerMutationInterceptor` is compile-time and never called in production. That's the real gap behind the user's "can people trigger it with code" question.

   **The state-machine argument, resolved:** A permission answers *may this principal write this field* (principal + resource + field); a transition rule answers *may this value become that value* (current data + proposed data). No principal-only system can express "posted invoices are immutable" — same accountant, same field, only the data differs. So it isn't a workaround *for* permissions; it's the shape permissions take when the decision depends on data. But the user is right that the *table* must be agent-authored data on the entity type, not a developer config file. Synthesis: **agent-authored, deterministically enforced.**

   **Round 4 — the Fable review broke two locked decisions.** R1 is the most consequential: `field_controls` ownership is per top-level metadata key, so `lines` is one atom — once a human edits any line, every agent-attributed write to `lines` is forced to approval. This collides with S1=A + S2=A. **My resolution:** run pricing inline inside the human's own save (semantically correct — the user pressed save), so `isHumanEdit` is true and neither the gate nor ownership applies. **The genuine surviving limit: a background recompute (re-pricing drafts after an FX move) is an agent write and WILL be blocked.**

   **Q1/Q2/Q3 verdicts adopted:** Q1 freeze in place, corrections are new documents (`entities.id` IS the identity that relationships point at, unlike `events.id` which is a stored-version id; Turkish e-invoice practice mandates correction by new document anyway) — added a `credit_note` entity type. Q2 per-entity-type durable audit opt-in (global would change failure semantics platform-wide). Q3 stage 1 derived types yes, **stage 2 reshaped to write-time rollups and the metric-compiler extension cancelled** — the repo invariant prescribes materializing at write time, and building the compiler fix is doing the migration we agreed not to do.
