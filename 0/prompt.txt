## 2. Key Technical Concepts

- **Branded types as structural enforcement**: `declare const validatedBrand: unique symbol`; no public constructor, so bypass is a compile error. Shared by `ValidatedEntityRowPatch` and `ValidatedEntityRowInsert`.
- **Deny-only verbs**: `deny(reason)`, `escalate(fields, reason)`. No `allow` — a rule can only NARROW the lattice.
- **Two-tier split**: `runMutationGate` = PERMISSION ("may this principal write this field", keyed on principalKind/ownership); `validateEntityRowPatch` = VALIDATION ("is the resulting state legal", no principal).
- **Batch-shaped isolate execution**: one isolate per (type, batch), not per row.
- **Two-pass compile**: `runScript` re-esbuilds its `source`, so stored artifacts must be IIFE + one ESM runner.
- **Guest-side control flow**: `deny`/`escalate` need zero `ivm.Reference` bridges.
- **"An approval hold may not manufacture an illegal state"** — the core invariant of the fix.
- **`changed()` must compare VALUES, not key presence** — because the seam passes the fully MERGED value set.
- **Rules are pure** — `noSdk` stub, no network/DB/fs, in an isolated-vm isolate. This makes speculative dry-run execution safe.
- `REVIEWER_CLI` has only TWO quota pools (pi is codex-backed); model via `CLAUDE_REVIEW_MODEL`.

The precise correction I was about to deliver: Lobu **does** have the rule text (`rules_source` is a plain text column, so displaying the source in the UI is trivially possible today). What Lobu cannot do is *derive structure* from it — you can't statically answer "what states exist" or "what's legal from `issued`" without understanding arbitrary JS.

**But the limitation is much weaker than I claimed**, because the rule is (a) pure — no SDK, no network, no DB, no fs, confirmed above — and (b) the evaluator already takes N independent `{committed, patch}` candidates in ONE batch and returns N verdicts positionally. So a **speculative dry-run** can answer "what's legal next" without any static analysis: take the candidate values (e.g. from `metadata_schema.properties.status.enum`), submit each as a candidate patch in one batch, and get back a verdict per candidate at ~3.2ms for the whole batch. That would let Owletto gray out illegal buttons and let the agent prompt list legal moves. It is not built, but it is a small addition on top of what exists, not a redesign.
