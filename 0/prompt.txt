2. **Key Technical Concepts:**

- **The three seams.** A write rule can run in exactly one of: **gate** (before the write — can refuse), **transaction** (inside the write — can allocate/mutate), **post-commit** (after — can only observe; where Behaviors live).
- **`runMutationGate` transaction context is INCONSISTENT** — `sql: getDb()` (pool client) on create/delete (`manage_entity.ts:320`, 4 sites); `sql: tx` on update (`entity-management.ts` ~line 700) and Behavior promotion. This refuted a claim I repeated multiple times.
- **Gapless ≠ unique.** `nextval()` is deliberately non-transactional and burns numbers on rollback. Gaplessness requires allocation inside the caller's transaction and forces serialization from allocation to COMMIT.
- **Vendor-extension mechanism**: `metadata_schema` is stored verbatim and AJV runs `strict: false`, so unknown `x-` keys round-trip and are ignored by validation. (`schemaExtras` does NOT exist — that was a false claim in a comment.)
- **`isolated-vm`** v6 (Node 22-24) / v7 aliased `isolated-vm-next` (Node 26+) in `packages/server`. `run-script.ts`: "terminates the run by disposing the isolate (uncatchable by the guest)." 60s default / 180s max wall clock.
- **Connector install rail**: `installConnectorDefinitionFromSource` (`packages/server/src/catalog/connector-definitions.ts:173`) takes `source_code`/`source_url`/`source_uri`/`mcp_url`, compiles, org-scopes, retains prior versions for `rollbackConnectorVersion`, never modifies the global catalog.
- **Connectors CAN generate relationships** — via reaction client (`entities.create/link/unlink/updateLink`) and declaratively via `attributions` on `eventKinds` (`EventAttributionRole = 'authored_by'|'about'|'mentions'|'belongs_to'`). Only **sync** is events-only.
- **`defineEntityType` returns pure DATA** (`{...config, kind: "entityType"}`); `lobu apply` ships it as `memorySchema.entityTypes`. A closure cannot ride that rail.
- **Codex's rule classification by state dependency**: proposal-local / current-row dependent / mutable-config dependent / cross-row dependent / write-transforming.
