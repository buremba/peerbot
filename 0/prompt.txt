       // The state field itself is exempt from the freeze: a frozen document may
       // still advance along a LEGAL transition, checked below. Without this, a
       // `frozen_from` at a non-terminal state strands the document one step
       // short of terminal forever — an invoice frozen at `issued` could never

       // that is not in `allowed[current]` is still denied by the transition
       // check, so a terminal state (empty `allowed`) remains fully sealed.
       const changed = Object.keys(req.fields).some(
         (field) =>
           field !== spec.field &&
           valueChanged(req.currentValues[field], req.proposedValues[field]),
       );
       if (changed) {
         return { outcome: "deny", reason: `${label} is frozen in state \"${currentState}\" and cannot be edited.` };
       }
     }

5. **Problem Solving:**

   **Both DB changes collapsed into existing primitives.** Rules go in `metadata_schema` as an `x-` keyword (`Record<String, Unknown>` on the contract + AJV `strict:false`, with `x-link-entity-type` as shipped precedent). Versioning is unnecessary because concurrency is already field-grained. Net: **zero schema changes** for the whole design.

   **The `x-transitions` premise was proven empirically on the PUBLISHED server** — added at runtime via `client.entitySchema.updateType`, read back PRESENT, and survived a full `lobu apply`. No deploy, no DDL.

   **Row-level read scope closed rather than deferred.** Relationship types carry no SQL predicate; the seam (`buildScopedQuery`, two entities CTEs) would take an `EXISTS` clause easily, but the tools/REST/search read paths are separate and a gate covering one of four leaks while looking like protection. Owner said operate on what I know; Prodma hides fields client-side, which is per-screen/per-field, so Lobu's tool-access tier covers it.

   **Two genuine gaps found by asking "are we set?"**: (1) no update hook, so a transition can refuse a write but never *cause* one — blocking journal entries on invoice post and stock movements on dispatch; (2) no numbering primitive (mitigated because Innova assigns the e-invoice number).
