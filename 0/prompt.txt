   **Third apply limitation (not yet fixed):** re-declaring a previously removed key does not re-adopt it — apply blocks on `<key> · definition` and refuses to overwrite a description it doesn't own.    **Connector edge import — research complete, proposal NOT yet delivered.** Corrected my own earlier overstatement: connectors **can** create entities and resolve identities declaratively via `eventKinds[kind].attributions` (with `EntityIdentitySpec` namespaces, `primary` immutable ids, `autoCreate`, `traits`), executed by `entity-link-upsert.ts`. That route is the precedent proving the need exists and was solved ad hoc. The recommended shape (to be surfaced for confirmation, since AGENTS.md forbids changing SDK surface without it): add a `relationships?: EntityRelationshipRule[]` sibling to `attributions` on an eventKind, declaring `{ relationshipType, target: {entityType, identities} }`, resolved through the existing identity resolver and writing `entity_relationships` — symmetric with what exists, declarative (no code execution in the connector), and inheriting identity resolution, `autoCreate`, and the live-triple dedupe semantics.
