## BLOCKERS

**B1 — Step 3's backfill is unsatisfiable for cross-org hosted-preview rows, and every fallback weakens the dedupe fence.**
- `connections.id` is globally unique (single-column PK on a global sequence — `db/migrations/00000000000000_baseline.sql:707-708,741-746,2765-2769`), so two orgs' rows cannot collapse by id collision. That is not the failure mode.
- The failure mode: `channel_messages` deliberately holds rows whose `organization_id` is the *binding* org while the connection belongs to a *different* org. Writer: `packages/server/src/gateway/connections/channel-transcript.ts:23` ("the binding's org for cross-org preview") and :7-9. Reader proof of the cross-org binding: branch (B) of `resolveBoundChannelRows` selects subscriptions where `connection_organization_id` ≠ the querying org (`packages/server/src/gateway/channels/bound-channels.ts:96-121`). The whole reason `channel_messages_org_dedup` is org-scoped is "a hosted preview connection can route one physical message to Behaviors in several organizations" (`db/migrations/20260719120000_channel_messages_org_dedupe.sql`, header comment).
- Consequence for a bigint FK: the binding org has **no** `connections` row for that slug (`connections_org_slug_unique` is per-org and partial on `deleted_at IS NULL` — baseline:3368-3371). Backfilling by `(organization_id, slug)` yields NULL for those rows; backfilling by slug alone resolves to *another org's* `connections.id` (a cross-tenant reference); leaving NULL breaks the dedupe arbiter — `channel_messages_org_dedup` is the `ON CONFLICT` target (`channel-transcript.ts:104-106`), and NULLs are distinct in a unique index, so webhook redeliveries duplicate rows for exactly the hosted-preview population that index was built for. The index IS load-bearing: it is the per-org idempotent-capture arbiter (tenant *read* isolation is via org predicates, `channel-transcript.ts:155`). The plan's "80 rows" framing hides all of this.
