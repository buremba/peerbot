## 2. Key Technical Concepts

- **Lobu Behaviors** (agent-facing name; `watcher` is internal DB/engine vocabulary — must not appear on exposed surfaces; `make pre-pr` enforces this)
- **Ref tokens**: `@[kind:id:label](path)` inline grammar serialized into prompts/messages
- **Behavior sources** (`sources[]` = `{name, query}[]`): both agent context AND the change-detection input
- **Change detection**: `fingerprintWatcherSources` → `queryContentData` → window fingerprint → `skip_if_unchanged` / window triggers, invoked by the scheduler (`watchers/automation.ts`)
- **Fan-out / assignments**: `create_from_version(version_id, entity_ids[])` clones a version into one `watchers` row per entity, sharing `watcher_group_id`
- **Per-assignment vs per-group state**: `create_version` cascades `current_version_id, version, name` to the whole group but writes `sources, schedule, timezone, triggers, next_run_at` to only the named row
- **`{{entityId}}` / `{{organizationId}}` / `{{query.*}}`**: template placeholders substituted into **bound parameters** (not string interpolation); unknown placeholders throw; user `$1` positional params rejected
- **Reaction scripts**: `reaction_script` / `reaction_script_compiled` / `reaction_input_schema` on `watchers`; `executeReaction` runs esbuild-compiled code in an **isolated-vm V8 isolate** over the typed `ClientSDK`; signature `default async (ctx, client, params?)`; 60s timeout; `MAX_ATTEMPTS = 3`; invoked from `complete-window`; input is the Behavior's **output** (`extracted_data`)
- **Monorepo**: Bun workspace, `packages/*`, owletto is a git submodule; `@lobu/core` subpath exports (root barrel banned in SPA by `check-no-core-barrel.mjs` — it's CJS and drags Node globals into the browser bundle)
- **Tiptap mention editor** with suggestion plugin, `handleClickOn`, node attrs round-tripped via `data-ref-*`
