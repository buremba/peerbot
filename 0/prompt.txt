## 2. Key Technical Concepts

- **Behavior windows**: `computePendingWindow` is only a *fallback*. `alignRequestedWindow` + `behavior-mode.ts:451` accept an agent-supplied `since`/`until`, aligned to granularity — "an agent-written window is indistinguishable in shape from a server-computed one." `readWindowCursor` = `MAX(window_start)` from `canvas_windows`. `behaviors.trigger` accepts only `behavior_id`, so it cannot express a range. The real path is `knowledge.read(behavior_id, since, until)` → 581-char JWT `window_token` → `behaviors.completeWindow`.
- **Device capability gating**: `AppState.swift:997` `currentCapabilities` gates each capability on a TCC probe AND a UserDefaults kill switch. `worker-api/device-reconcile.ts:7` pauses auto-wired feeds whose capability isn't served. The server correctly follows the device.
- **`event_kinds` is a CLOSED allowlist once non-empty.** `connector_definitions.feeds_schema` is code-derived via `connector-definition-install.ts:322`, but synced by an **hourly cron** (`jobs.ts:288`), NOT at deploy — creating a silent write-rejection window during rollout.
- **Submodule merge order** (`feedback_merge_owletto_pr_last_not_first.md`): merging an Owletto PR early turns `check-drift` red on EVERY open lobu PR. Safe order: parent green (incl. ui-review) → merge Owletto → repin to squash SHA → merge parent. On submodule-pointer branches use `git merge`, never rebase.
- **`ui-review` gate**: requires `ARTIFACT=<hosted HTTPS>`; records proof on the exact merged Owletto PR. A changed head re-owes it.
- **False-green class**: `feeds.last_sync_status: success` with 0 items; `runs.status: completed` with no output; `connections.test` "Credentials valid" during a scope-insufficient outage.
- **MCP tool limits**: `query_sql` allowlist excludes `runs`, `device_workers`, `auth_profiles`, `watchers`. `behavior_versions` has no `behavior_id`/`config`/`sources`; Behavior sources live on `behaviors.sources`.
