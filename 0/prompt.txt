2. **Key Technical Concepts:**
- **Release pipeline duality:** merging a release PR fires `Build and Push Images` TWICE — once on `push`, once on `release`. `trigger-package-publish` is gated `if: github.event_name == 'release'`, so `skipped` on the push twin is normal. Prod rolls from the **push-event** image ~90 min before npm publishes.
- **`make pre-pr-remote` bases its patch on the REMOTE branch** (`Base: origin/<branch>`, `Merge base: <sha>` in its header), not local HEAD. Rebasing without pushing gates a stale tree.
- **Depot serializes org-wide**; a newer dispatch silently cancels a peer session's gate. Peer sessions log to different paths (`/tmp/prpr2.log`, `/tmp/claude-<id>-cwd`). `pkill -f "make pre-pr-remote"` can kill a teammate's gate.
- **`check-drift` / owletto merge order:** merging an owletto PR before its parent pointer bump turns `check-drift` red on EVERY open lobu PR. Order: parent green → merge owletto → repin → merge parent. `make ui-review` only accepts a pointer equal to a **merged** owletto PR's `merge_commit_sha`.
- **Generated-client guard** path-matches `packages/core/src/contracts/tools/**` and `packages/server/src/gateway/routes/**`; escape hatch `[client-regen-not-needed]` (inapplicable when the emitted schema really changes).
- **Deployed-prod-SHA recipe:** namespace `summaries-prod`, deployment `summaries-app-lobu-app`, image tag `YYYYMMDD-HHMMSS-NNNNNN` where NNNNNN = "Build and Push Images" run number; join via `gh run list`.
- **Branch-protection check resolution:** must take the LATEST check-run per name (an earlier cancelled run is superseded).
- **Biome scoping:** lobu uses `biome check --config-path config/biome.config.json`; owletto has no `biome.json` and its script is `biome lint src`.
