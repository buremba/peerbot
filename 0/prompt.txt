5. **Problem Solving:**

   Established the root cause is not a missing renderer but a **missing contract**: `notifications.send` accepts presentation (a `card`) where it should accept intent (a schema), and a button's `actionId` *is* its routing key, so only the server can build a working one. Proved it live on prod: events **4828079** and **4828080** in org `buremba` are byte-identical in storage; both return `interaction_type: null` while the inbox contract already selects and consumes that column. Settled the layering (ask = contract, presentation = derived/plural, transport = per-surface). Determined binary asks work natively on web + Slack + Telegram with zero frontend work.
