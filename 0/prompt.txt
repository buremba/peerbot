## 2. Key Technical Concepts

- **Lobu Behaviors** run on **windows**; `computePendingWindow` (`packages/server/src/utils/window-utils.ts`) chains off the last window's `window_start` and clamps to the current period. No hourly granularity — an hourly cron gets a DAILY window.
- **`canvas_windows`** table is ground truth for behavior output: `content_analyzed`, `extracted_data`, `run_id`. Errors hide in `extracted_data->'run_metadata'->>'error'`, NOT `runs.error_message`.
- **`lobu apply`** is a declarative config→prod sync that is a *blind overwrite* with no drift detection.
- **Device workers**: Owletto Mac app + Chrome extension; `worker_claim_timeout` means the device is gone, not a connector bug.
- **Notifications are events**: no notifications table (dropped by `20260513200000_notifications_as_events.sql`); state spans `events` + `notification_targets` + `runs`, joined at read time.
- **Entity resolution**: `x-lobu-resolution` rules on `entity_types.metadata_schema`; `discovery.ts` unions candidates only on identical normalized keys.
- **Evals program** (#2564): `runs.outcome` taxonomy (PR 1 merged as #2566, squash `b0198396`), capture mode (PR 2, unbuilt).
- MCP tools: `query_sql` (table allowlist), `query_sdk` (read), `run_sdk` (write), `search_sdk`.
- Gates: `make pre-pr`, `make review-fix`, `make review`, `make ui-review`, `make task-setup NAME=<slug>`.
