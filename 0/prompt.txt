2. Key Technical Concepts:

- **Connector routing / claim eligibility** (`packages/server/src/worker-api/poll.ts:456-490`): fleet lane requires `con.device_worker_id IS NULL`; device lane requires `con.device_worker_id = <me>` AND (`cd.required_capability IS NULL` OR ∈ authorized). NULL capability is **fail-open** on the device lane.
- **SDK connector declaration contract** (`packages/connector-sdk/src/connector-types.ts:76-90`): `requiredCapability?: string` — "Unset = any worker (default API/browser fleet)"; `runtime?: ConnectorRuntimeInfo` — "Present only for device-bound connectors. Omitting this field means the connector runs on the server-side worker fleet (cloud)."
- **`BridgeOnlyConnector`** (`connector-runtime.ts:166-172`): device-bound connectors are implemented **natively in the bridge** (Swift/extension JS); server holds only the definition, with stubs that throw.
- **Capability allowlist** (`packages/core/src/capabilities.ts`): `OS_CAPABILITIES = ["os.shell", "os.files", "os.notifications"]`; `MAC_DEVICE_CAPABILITIES = [screentime, local_directory, healthkit, photos, whatsapp_local, calendar, reminders, system_audio, computer_use]`; `PLATFORM_ALLOWLIST.macos = [...OS, ...BROWSER, ...MAC_DEVICE]`. **`os.files` already exists and is already allowlisted for macos.**
- **Worker protocol** (from `LobuClient.swift:541-610`): `POST /api/workers/poll {worker_id, capabilities, platform, app_version, label, connector_manifests}`, `/heartbeat {run_id, worker_id}`, `/stream {type:"batch", run_id, worker_id, items}`, `/complete {worker_id, run_id, items_collected, checkpoint, error}`.
- **`DeviceConnectorManifest`** (`worker-api/device-manifests.ts`): carries `required_capability: string` (required) and `runtime: { platforms, scopes?, nix? }` — devices can ship their own connectors.
- **REST admin API access without MCP**: `curl -X POST https://app.lobu.ai/api/buremba/<tool>` with `Authorization: Bearer $(lobu whoami --json | .accessToken)`. `query_sql` arg is `sql` (not `query`). `query_sdk` is READ-ONLY; writes require `run_sdk`. Scripts must use `export default async function (_ctx, client) {...}` (no top-level await/return).
- **`query_sql` allowlist**: behavior_versions, behaviors, canvas_windows, channel_messages, connections, connector_definitions, entities, entity_relationship_types, entity_relationships, event_classifications, events, feeds, oauth_clients, oauth_tokens, user. `runs` is NOT included — use `client.operations.listRuns({ feed_ids, connector_key, created_after/before, limit })`.
- **False-green class**: `runs.status: completed` with 0 items; a populated `events` table alongside a `failed` feed means data arrived via a path that no longer runs.
