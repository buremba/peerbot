2. **Key Technical Concepts:**
   - **Two-tier policy split**: queryable (declarative policy rows, answers "may I?" and gates reads) vs enforceable (per-type code at the write seam)
   - **Deny-only verbs**: `deny(reason)`, `escalate(fields, reason)`. **No `allow`** — a rule can narrow the lattice, never widen it
   - **Branded types as structural enforcement**: `declare const validatedBrand: unique symbol`; no public constructor, so bypass is a compile error
   - **Batch-shaped isolate execution**: one isolate per (type, batch), not per row
   - **Per-row isolate serialization is already free**: lock at `entity-management.ts:958` precedes rule position `:1101`
   - **Event-loop starvation is per-process, not per-row**
   - **Compile memoization** by content hash (`computeCodeHash`)
   - **Guest-side control flow**: `deny`/`escalate` need zero `ivm.Reference` bridges
   - **Inert-then-arm rollout**: schema before code so a rolling deploy never runs new code against an old table
   - `REVIEWER_CLI` has only **two** quota pools (pi is codex-backed)
