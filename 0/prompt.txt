## Things that contradict the brief / prior work

1. **The allocator's doc comment cited two things that don't exist.** It claimed `x-numbering` works "exactly like `x-transitions`" and that `upsertEntityType`'s `schemaExtras` carries `x-` keys. `git grep x-transitions origin/main` (after `git fetch`) returns nothing, and `schemaExtras` appears nowhere but that comment. The mechanism is real but different: `manage_entity_schema` stores `metadata_schema` verbatim and the AJV singleton runs `strict: false`, so unknown `x-` keys round-trip and are ignored by validation. I corrected the comment and the new suite proves the round-trip through the real `createType`.

2. **`entity-link-upsert.ts` is a genuine bypass.** `createEntityWithIdentities` has its own `INSERT INTO entities`, retried across up to three slug variants, and never allocates — a numbered type auto-created from a connector-extracted link lands unnumbered. I did *not* wire it: the retry loop would need restructuring into one transaction, and it's a different concern. Recorded in the module doc.

3. **`createType` rewrites `_` to `-` in slugs** (`args.slug.toLowerCase().replace(/[^a-z0-9-]/g, '-')`). Cost me one red run; worth knowing before you write ERP type slugs.

4. **A numbered field must not be in the schema's `required` array**, or `validateEntityMetadata` rejects every create before the allocator is reached. Noted in the fixture comment. This is a real footgun for whoever authors the invoice type.

5. **The old suite dropped the counter table in `afterAll`.** Harmless while the table was test-owned; now it would have silently broken every later suite in the shared DB. Removed — cleanup is now the `entity_types` delete cascading the counter rows.
