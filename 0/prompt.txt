2. **Key Technical Concepts:**
   - **Device connector manifests**: Chrome extension POSTs `connector_manifests` on every `/api/workers/poll`; server validates, hashes, stores in `device_workers.connector_manifests`, then reconciles into `connector_definitions`.
   - **`manifest_hash` is server-computed** — no generator exists in the repo. Optional input; stale value = rejection.
   - **All-or-nothing manifest acceptance**: one invalid manifest sets `accepted = false`, which preserves the *previous* inventory for the whole device.
   - **Chrome MV3 unpacked-extension caching**: `manifest.json` is re-read on restart, but the service-worker JS module graph is served from `Default/Service Worker/ScriptCache`.
   - Chrome extension id derived from `manifest.key`, so store and unpacked builds share an id; `location: 4` = unpacked, `1` = Web Store; extension settings live in `Secure Preferences` on macOS.
   - Chrome 136+ refuses `--remote-debugging-port` on the default profile.
   - **Owletto tab reaper**: `OWNED_TABS` registry, 1-min alarm, `EXTENSION_TAB_TTL_MS` = 5 min. `release_tab` transfers ownership to the user.
   - **Accessibility tree walker**: `accessibility-tree.js` `keepElement` → `isVisible` + `inViewport` + `isInteractive`; viewport-filtered, so below-fold elements vanish.
   - `lobu call <tool> --input-file` CLI over `POST /api/:orgSlug/:toolName`; requires `LOBU_MEMORY_URL=https://app.lobu.ai` (bare `lobu.ai` 404s; `--url` trips a credential guard).
   - ConnectorCompiler requires single-file sources (no local imports).
   - Connector version retention: reinstalling a retained version with different code is refused; must bump.
   - Mutation testing to validate new tests.
