   The answer (from context already gathered): they are different things. `entity_identities` is a **lookup/naming** table — `(organization_id, namespace, identifier) → entity_id`, live-unique per org — answering "which entity does this identifier name?" (e.g. `slack_user_id` = `T09:U123` → entity 42). `entity_relationships` is an **edge** table between two entities with a `relationship_type_id` (`member_of`, `authored_by`, `works_at`) — answering "how do two entities relate?" (e.g. person 42 `member_of` channel-resource 7). Identities are how an external system's id resolves to an entity; relationships are the graph between entities. `member_of` edges (the read ACL) are relationships; `slack_user_id` claims are identities. You can't express "this Slack id IS this person" as a relationship without inventing an entity per identifier.
